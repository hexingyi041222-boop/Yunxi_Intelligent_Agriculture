# AI方案设计

## 1. AI方案总体架构

芸析智农以“**多源感知、端云协同、知识增强、安全存证**”为核心，将模型能力嵌入农业生产流程，而非提供孤立的图片识别工具。

~~~text
感知层
├─ VisionKit：叶片、果实与病斑图像
├─ SpeechKit / 文本：症状描述、种植阶段、用户问题
└─ 自研终端：空气温湿度、光照、土壤温度
        ↓
通信层
├─ 4G → OneNet → 后端数据接口
└─ HarmonyOS分布式能力：手机、PC与设备间任务流转
        ↓
模型层
├─ 云端Qwen2.5-VL-3B：视觉初筛与低延迟响应
├─ RAG植物知识库：检索病害与农事规范
└─ 传感器分析：阈值、趋势及环境异常判断
        ↓
应用层
├─ 解释性诊断、风险等级、每日种植计划
├─ SSE流式回传、TTS播报、主动提醒
└─ 人工复核、执行反馈与PC端工单
        ↓
存证层
└─ SM3摘要 + SM2签名 + SM4加密，形成可校验记录
~~~

## 2. 多模态融合诊断链路

### 步骤一：输入采集

用户通过VisionKit拍照，并以文字或SpeechKit补充症状、发生时间及近期操作；系统自动关联地块、作物阶段和最近一段时间的环境数据。为降低输入成本，图片是主输入，语音和传感器数据作为上下文补充。

### 步骤二：路由与校验

系统检查图片格式、清晰度、主体占比和字段完整性。图片模糊时引导重拍；缺少传感器数据时允许继续，但在报告中标记信息不足。路由器根据任务类型决定执行植物识别、病害诊断、环境异常分析或综合问答，并生成统一任务ID。

### 步骤三：三路并发推理

| 推理分支 | 输入与职责 | 标准化输出 |
| --- | --- | --- |
| 视觉诊断 | Qwen2.5-VL-3B分析图像与症状描述 | 候选病害、视觉证据、置信度 |
| RAG检索 | 按作物、症状、地域和生育期召回知识 | 病害特征、操作规范、来源片段 |
| 传感器分析 | 对温湿度、光照和土壤温度做阈值及趋势判断 | 环境风险、异常时间、影响方向 |

三路结果不直接拼接，而是先转换为统一JSON结构。业务规则检查证据是否一致：若视觉判断为真菌性病害，同时环境数据持续高湿，系统提高相关风险权重；若图像结论与环境条件冲突，则降低置信度并触发复核。融合Prompt只允许模型基于三路证据生成结论，不允许补造未提供的农药名称、剂量或环境数据。

### 步骤四：结果融合与生成

生成器按照“问题摘要—可能原因—证据依据—风险等级—今日行动—后续观察—是否需人工复核”的结构输出。建议强调时间、步骤、适用条件和注意事项，使结果能够直接转化为每日计划，而不是停留在病理学解释层面。

### 步骤五：流式回传与呈现

后端通过SSE分段返回分析状态和最终内容，用户无需等待完整长文本。UI先展示风险等级和关键动作，再展开证据与知识来源；TTS只播报已确认的核心建议。网络中断时保存任务状态，恢复后继续拉取结果，避免重复提交。

## 3. 端云协同策略

端侧模型部署于优云智算云端GPU4090，采用约3.75B参数的Qwen2.5-VL-3B-Instruct。经LoRA微调后，域内病害识别准确率超过96.0%，ViT处理时延为0.15—1.23秒，编码速度约1662 tokens/s。

| 端侧职责 | 云端职责 |
| --- | --- |
| 高频图像初筛、基础问答、弱网或离线响应 | 多病因关联、长上下文推理与疑难样本复核 |
| 原始数据优先本地处理，降低隐私风险 | 融合更多知识证据，处理端侧能力边界外任务 |
| 快速返回候选结果与置信度 | 对冲突结果进行二次判断并补充解释 |

切换由置信度和业务风险共同决定：低置信度、三路证据冲突、连续处理失败或涉及高风险用药时进入云端；网络不可用时仅返回端侧初筛，并明确标记“待复核”，不伪装为完整结论。

## 4. Prompt工程与RAG设计

RAG知识库按“作物—生育期—症状—病因—防治措施”组织，内容包括病害图谱、农事操作规范、传感器阈值说明和典型案例。资料入库前进行来源标记、版本管理、文本切分与元数据补全；检索阶段结合关键词和语义召回，并按作物匹配度、时效性及来源可信度重排。

System Prompt约束模型角色为“农业生产辅助决策助手”，要求：仅依据输入和检索证据回答；区分事实、推测与待确认信息；禁止在证据不足时输出确定性用药方案；必须给出可执行计划。结构化输出包含：任务日期、行动项、执行时间、所需材料、操作步骤、风险提示、复查节点和引用来源，便于前端直接生成计划卡片与提醒。

## 5. AI安全与可信设计

诊断完成后，系统对任务ID、输入摘要、模型版本、知识来源、输出结果和人工修改记录生成SM3数字摘要，通过SM2完成身份签名，并使用SM4保护敏感内容。该机制形成可验证的防篡改记录，使结果变更能够被发现和追踪。

产品界面同步承担风险控制职责：展示置信度、证据来源、数据缺失项和模型版本；低置信度结果使用审慎措辞，并提供云端或农技人员复核入口。用户执行后的反馈与人工修订继续进入存证链路，使AI结论、人工判断和实际效果形成可审计闭环。产品始终定位为**辅助决策工具**，不以流畅表达替代专业确认。
