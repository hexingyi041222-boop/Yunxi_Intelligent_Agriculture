# 系统架构与接口

## 1. 系统总体架构

芸析智农采用“**端侧感知与交互、云端数据与AI计算、可信安全存证**”的分层架构。各层通过标准接口解耦，使硬件、模型和应用可以独立升级。

~~~text
端：现场感知与用户交互
├─ 农业终端：DHT11、BH1750、DS18B20、4G模块
├─ 鸿蒙App：ArkTS / ArkUI
│  ├─ VisionKit拍照、SpeechKit语音
│  ├─ NotificationKit提醒、TTS播报
│  └─ 手机端任务执行与反馈
└─ Web / PC：数据看板、设备管理、工单调度
        ↓ 4G / HTTPS / SSE / 鸿蒙分布式能力
云：接入、存储与计算
├─ OneNet：设备鉴权、遥测数据接收
├─ 腾讯云业务后端：用户、地块、任务、权限与接口编排
├─ InfluxDB：温湿度、光照和土壤温度时序数据
├─ 优云智算GPU 4090：LoRA微调Qwen2.5-VL-3B推理
├─ RAG植物知识库：病害与农事规范检索
└─ 云端LLM：低置信度及疑难样本复核
        ↓
可信存证
└─ Device Security Kit：SM3摘要、SM2签名、SM4加密
~~~

业务后端作为统一编排层，前端不直接调用模型或数据库，从而集中管理鉴权、限流、版本、日志和降级策略。

## 2. 核心数据流转与接口交互

一次完整AI诊断按以下顺序执行：

1. App通过图像上传接口提交图片，或先将SpeechKit语音转为文本；随后调用【多模态诊断接口】，提交地块、作物、描述和图片ID。
2. 后端完成身份鉴权、文件格式检查、图片质检及任务去重，并生成task_id与trace_id。
3. 后端根据地块和时间范围调用【传感器查询接口】，从InfluxDB获取环境快照；同时并发调用【视觉诊断API】和【RAG检索API】。
4. 融合服务将视觉候选、知识片段和环境风险转换为统一结构，计算综合置信度并生成解释性建议。
5. 若置信度低、三路证据冲突或涉及高风险处置，后端调用【云端LLM复核API】；网络异常时保留初筛结果并标记待复核。
6. 任务进度、诊断结论和每日计划通过SSE推送至App；前端展示风险等级、证据与人工复核入口，并按需TTS播报。
7. 最终结果、模型版本、知识来源和人工修改记录生成摘要并提交安全存证，用户执行反馈继续关联同一task_id。

## 3. 关键接口设计（API Mock）

### 3.1 设备遥测上报

**POST** `/api/v1/device/telemetry`

| 入参 | 类型 | 说明 |
| --- | --- | --- |
| device_id | string | 设备唯一编号 |
| timestamp | integer | 毫秒时间戳 |
| metrics | object | 空气温湿度、光照、土壤温度 |
| nonce / signature | string | 防重放随机数与设备签名 |

~~~json
{
  "device_id": "DEV-001",
  "timestamp": 1793764800000,
  "metrics": {"air_temp": 26.4, "humidity": 78, "light_lux": 18300, "soil_temp": 22.1}
}
~~~

~~~json
{"code": 0, "trace_id": "tr_1024", "accepted": true}
~~~

后端校验签名和时间窗口后写入InfluxDB；重复时间戳采用幂等处理，异常值保留原始记录并增加quality_flag。

### 3.2 多模态诊断任务

**POST** `/api/v1/diagnose`

| 入参 | 类型 | 说明 |
| --- | --- | --- |
| plot_id / crop | string | 地块与作物信息 |
| image_id | string | 已上传图片资源ID |
| description | string | 文字或语音转写内容 |
| telemetry_window | string | 环境数据查询时间窗口 |

~~~json
{
  "plot_id": "P-08",
  "crop": "tomato",
  "image_id": "img_ab12",
  "description": "叶片发黄，近三天持续降雨",
  "telemetry_window": "72h"
}
~~~

~~~json
{
  "code": 0,
  "task_id": "diag_20261104_001",
  "status": "queued",
  "stream_url": "/api/v1/diagnose/diag_20261104_001/stream"
}
~~~

### 3.3 诊断结果流

**GET** `/api/v1/diagnose/{task_id}/stream`，响应类型为`text/event-stream`。

~~~text
event: progress
data: {"stage":"fusion","percent":70}

event: result
data: {"risk":"medium","confidence":0.87,"need_review":false,"actions":["检查排水","24小时后复拍"]}
~~~

客户端携带Last-Event-ID重连；服务端从最近事件继续推送，防止断网后重复创建诊断任务。

## 4. 多端协同与任务流转

PC端创建工单后，业务后端保存统一work_order_id、负责人、截止时间和版本号，并向手机端推送任务。鸿蒙分布式软总线约8毫秒的链路能力用于近场设备发现和任务接续，多端同步仍以云端状态为最终依据，避免设备离线导致状态分叉。

状态采用“待接收—处理中—待复核—已完成—已归档”流转。每次更新携带版本号，后端使用乐观锁处理并发修改；手机离线时先保存本地操作，恢复网络后按时间和版本合并，PC端可查看执行图片、AI建议及反馈记录。

## 5. 安全与合规设计

用户端接口采用访问令牌与角色权限控制，区分农户、组织管理员和农技人员；设备接口使用device_id、timestamp、nonce及签名校验，防止伪造设备和重放请求。所有接口使用HTTPS，并通过trace_id记录调用链，敏感日志不保存语音原文和完整身份信息。

诊断落盘前，后端对输入摘要、模型版本、结果和人工修订生成SM3指纹；Device Security Kit使用SM2完成签名验证，并通过SM4加密敏感字段。存证接口返回record_id与摘要，业务库仅保存索引和校验信息。后续查询时重新计算摘要并比对，从而发现数据是否被修改，同时保留操作者、时间与版本，满足责任追踪和B端审计需求。
