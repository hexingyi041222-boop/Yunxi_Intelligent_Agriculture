# 用户研究与需求洞察

## 研究背景与目标

农业数字化并不缺少传感器、识别模型或管理系统，真正的难点在于：技术能力能否进入真实生产流程，并转化为用户看得懂、愿意用、能够执行的决策依据。

本次用户研究围绕农户、家庭农场、合作社、种植基地、农业企业及农技服务机构展开，重点理解不同主体在**数据采集、风险判断、农事执行和服务协同**中的障碍。研究目标不是简单罗列功能需求，而是识别影响产品落地的关键矛盾：如何降低数字工具使用门槛，如何让AI结论具备可信依据，以及如何将一次诊断延伸为持续的生产管理闭环。

## 目标用户画像

### C端：农户与家庭农场

典型用户通常管理一个或少量地块，数字化能力有限，日常决策依赖个人经验。其核心诉求是以较低学习成本掌握作物状态，在病害扩大或环境指标异常前获得提醒，并得到明确的处理步骤。

- **典型特征**：**人员少、任务杂**，主要通过手机获取信息，对复杂数据看板接受度较低；
- **核心诉求**：**低门槛监测、拍照识别、病害提示和直观的每日种植计划**；
- **当前痛点**：**设备数据分散、病害难判断**，识别结果往往只有名称，缺少“下一步做什么”。

### B端：合作社、农企与农技服务机构

B端用户管理多个地块、设备或服务对象，更关注管理效率、过程留痕与组织协同。合作社和种植基地需要统一查看地块状态、分派任务并沉淀生产记录；农业企业及园区需要多设备接入、分级权限、数据看板和系统定制；农技机构则需要远程查看现场信息，通过图文问答完成诊断，并积累可复用的案例档案。

其共同痛点是信息跨主体流转效率低：管理者看不到实时现场，成员执行缺少统一标准，农技人员难以持续覆盖分散地块，服务结果也缺乏可追踪记录。

## 核心痛点洞察

1. **数据获取端——监测碎片化**：传感器、图像和农事记录分散在不同设备或人工台账中，数据无法形成连续的作物档案，异常也难以及时被发现。
2. **决策诊断端——高度依赖经验**：基层用户面对病斑、缺素或环境异常时难以准确区分原因，单一图像识别又容易忽略温湿度、土壤等关键背景。
3. **执行落地端——识别与任务脱节**：用户获得病害名称或指标预警后，仍不知道何时处理、采取什么措施、如何验证效果，建议无法转化为行动。
4. **服务触达端——专业覆盖不足**：农技人员数量有限，服务对象和地块分散；缺少统一数据与案例记录，使远程判断、协同跟进和经验复用成本较高。

## 需求转化：从痛点到产品功能

| 用户痛点 | 用户需求 | 产品功能映射 |
| --- | --- | --- |
| 不清楚地块实时状态 | 自动、连续地获取环境数据 | 自研监测终端与多传感器实时采集 |
| 设备和记录相互割裂 | 在一个入口统一查看 | 鸿蒙应用统一接入设备、地块与记录 |
| 无法判断病斑或异常原因 | 获得低门槛、可信的辅助诊断 | 图像、传感器与知识库融合诊断 |
| 不知道如何施肥或处理病害 | 获得直观、可执行的每日计划 | AI生成种植计划与分步骤农事建议 |
| 管理者难以及时发现风险 | 主动获知异常并确定优先级 | 阈值监测、AI风险分级与消息提醒 |
| 农技服务难以远程持续跟进 | 查看完整上下文并沉淀案例 | 远程图文问答、历史数据与案例库 |

## 产品机会与切入点

用户需要的并不是更多孤立工具，而是一条从现场感知到决策执行的低门槛路径。因此，芸析智农选择“**移动应用 + 自研终端 + 多模态AI**”作为切入点：终端解决数据持续获取问题，移动端降低使用门槛，多模态AI将环境数据、作物图像和农技知识转化为可执行建议。

产品的核心机会在于建立“**感知—诊断—建议—执行—反馈**”闭环。通过可解释的诊断依据、风险等级、知识来源及人工复核提示建立信任；通过每日计划、异常提醒和任务留痕推动建议真正落地。
