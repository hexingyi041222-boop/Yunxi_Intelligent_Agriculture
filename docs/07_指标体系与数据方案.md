# 指标体系与数据方案

## 1. 整体指标体系：OSM模型

芸析智农通过OSM模型将业务目标、产品策略与数据度量对齐，避免只关注模型准确率而忽略真实生产价值。

| 指标层级 | Objective | Strategy | Measurement |
| --- | --- | --- | --- |
| 业务结果 | 提升资源利用率，降低病虫害损失 | 以传感器和AI建议辅助精准水肥管理及风险预警 | 节水率、节肥率、病虫害损失降低率、建议执行率 |
| AI模型 | 提升诊断可信度与复杂问题处理能力 | Qwen2.5-VL-3B多模态诊断，RAG增强 | 融合诊断准确率、幻觉率、人工复核率、建议采纳率 |
| 产品体验 | 降低农业数字工具使用门槛 | 拍照/语音输入、流式反馈、多端同步与主动提醒 | 任务完成率、平均完成时间、误操作率、周活跃地块数 |

产品北极星指标为**周有效决策闭环数**：用户完成数据采集或提问、获得AI建议，并提交执行结果的任务数量。

## 2. 核心指标定义与埋点方案

| 指标名称 | 计算逻辑 | 数据来源 |
| --- | --- | --- |
| 节水目标达成率 | 实际节水率÷30%；实际节水率=（基准用水量－本期用水量）÷基准用水量 | 灌溉记录、设备数据、用户反馈 |
| 节肥目标达成率 | 实际节肥率÷25%；按同作物、同面积和同周期基准对比 | 施肥记录、地块档案 |
| 病虫害损失降低率 | （基准损失－试点损失）÷基准损失 | 病害记录、产量记录、人工核验 |
| 意图识别率 | 正确路由的有效任务数÷已标注任务总数 | App输入、路由日志、人工标注 |
| 多模态诊断准确率 | 诊断正确样本数÷有效标注样本总数 | Golden Set、模型日志、复核结果 |
| 人工复核率 | 进入人工复核任务数÷AI完成任务总数 | 后端任务日志、复核工单 |
| AI建议采纳率 | 转为计划或确认执行的建议数÷总建议数 | 计划创建、执行反馈埋点 |
| 端到端任务完成率 | 成功展示结果的任务数÷发起任务数；当前98.7% | App埋点、SSE及后端日志 |
| 平均完成时间 | 从提交到可操作结果展示的平均耗时；当前4.67秒 | 客户端与服务端时间戳 |
| 误操作率 | 取消、重复提交或错误路径次数÷总操作次数；当前1.3% | App点击流、异常日志 |

埋点以统一task_id关联用户输入、模型版本、知识召回、传感器快照、建议结果和执行反馈。业务指标必须采用同作物、同面积、同季节的基准组，避免将天气或管理差异误判为产品效果。

## 3. 全链路数据流转方案

~~~text
DHT11 / BH1750 / DS18B20 + 用户图片、语音
→ 4G传输至OneNet，完成设备鉴权与实时接收
→ InfluxDB存储时序数据，腾讯云后端管理任务和业务数据
→ 优云智算GPU 4090运行LoRA微调的Qwen2.5-VL-3B
→ RAG知识检索、传感器分析并发；疑难任务交由云端LLM复核
→ 融合生成诊断、依据和每日计划
→ Device Security Kit生成摘要、签名及加密存证
→ 鸿蒙App / PC端展示、提醒、工单流转与执行反馈
~~~

链路中每次诊断均保存任务状态与处理时间，但图片、语音和身份信息分区存储。

## 4. 数据获取与治理策略

冷启动阶段使用阿里云公开数据集训练和验证基础能力，入库前记录来源、许可范围、作物类别和标注质量；上线后，用户图片、语音及环境数据采用最小化采集原则，身份字段使用用户ID映射，图片去除无关人物与定位信息，敏感字段加密并按角色授权。

用户“已执行/未执行、效果改善/无变化、补充照片”形成结果标签。低置信度、模型误诊和人工修改样本进入Bad Case池，经脱敏、去重和人工确认后加入私域数据集，用于RAG更新或下一轮LoRA增量微调，形成“使用—反馈—清洗—训练—回归”的数据飞轮。

## 5. 数据安全与合规

系统使用SM3生成诊断与生产记录摘要，使用SM2完成签名验证，并以SM4保护敏感内容，形成可校验的防篡改存证；任何结果或人工修订都保留版本和操作主体，支持审计追踪。

“数据不外流”的产品含义是：数据在授权的私域与受控算力环境中处理，不提交第三方闭源公共模型API，也不用于未经授权的训练。面向合作社和农业企业，可进一步提供租户隔离、角色权限、数据保留周期和导出审计能力，以满足B端对数据主权、责任追踪及合规管理的要求。
