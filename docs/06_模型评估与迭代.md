# 模型评估与迭代

## 1. 评估目标与北极星指标

芸析智农的模型评估不以单一准确率作为结论。农业诊断最终需要完成“输入问题—获得可信建议—理解并执行”的业务任务，因此评估体系同时覆盖**模型效果、系统性能、交互质量和风险控制**。

北极星指标定义为：**有效诊断闭环率**，即用户成功提交多模态任务、获得具备证据和行动步骤的报告，并完成查看或反馈的任务占比。识别准确率用于衡量模型能力，任务完成率、时延和误操作率则决定能力能否真正被用户使用。

## 2. Golden Set测试集构建策略

Golden Set应与训练集严格隔离，并按作物、病害、季节、图像质量和输入模态分层抽样。每条样本包含原始图片、文字或语音描述、传感器数据、标准标签、证据来源、可接受建议及风险等级，由模型成员与农技人员共同审核。

| 样本类型 | 构建方式 | 主要验证目标 |
| --- | --- | --- |
| 正常样本 | 健康植株、常见生长状态及正常环境区间 | 控制误报，避免把正常现象判断为病害 |
| 常见病害 | 覆盖主要作物、典型症状和不同严重程度 | 验证域内准确率及建议完整性 |
| 长尾样本 | 罕见病害、早期症状、复合病因和相似病斑 | 检查模型边界与低置信度识别能力 |
| 信息冲突 | 图片显示发黄，但湿度、温度等数据不支持对应病因 | 验证多模态证据冲突处理与复核触发 |
| 对抗样本 | 模糊、遮挡、逆光图片，方言、噪声和不完整语音 | 验证输入质检、澄清提问及拒答能力 |

测试集采用版本号管理，新增Bad Case只能进入下一版本，不能回填当前测试结果，避免指标被“刷高”。

## 3. 核心评估指标矩阵

| 维度 | 指标 | 阶段目标或基准 |
| --- | --- | --- |
| 识别效果 | 病害识别域内准确率 | LoRA微调后≥96.0% |
| 长尾能力 | 罕见病害召回率、低置信度识别率 | 统一测试后补录，优先确保可触发复核 |
| 模型性能 | ViT处理时延 | 0.15—1.23秒 |
| 编码性能 | 编码速度 | 约1662 tokens/s，作为环境基准 |
| 系统可用性 | 端到端任务完成率 | 当前实测98.7%，目标保持≥98% |
| 交互效率 | 平均任务完成时间 | 当前实测4.67秒，分位数待补测 |
| 交互质量 | 误操作率 | 当前实测1.3%，目标≤1.3% |
| 可信安全 | 高风险无依据结论率 | 目标为0；一般幻觉率统一标注后补录 |
| 建议质量 | 证据引用完整率、计划可执行率 | 由规则检查与人工抽检共同评估 |

准确率需同时报告混淆矩阵、Precision、Recall和F1，避免类别不均衡掩盖长尾病害表现；时延需区分模型处理时间与4.67秒的系统端到端体验时间。

## 4. Bad Case分析与迭代机制

Bad Case按“误诊、漏诊、证据冲突、知识召回错误、建议不可执行、交互失败”分类，统一记录模型版本、Prompt版本、检索片段、传感器上下文和用户反馈。

~~~text
线上/测试发现错误
→ 自动保存任务上下文并脱敏
→ 置信度或风险规则判断
→ 云端LLM生成复核意见
→ 人工确认最终标签与原因
→ 数据去重、清洗和难例分层
→ 加入增量训练集进行LoRA微调
→ Golden Set回归测试
→ 指标达标后灰度更新
~~~

云端LLM仅承担疑难分析和候选解释，不直接作为真实标签。复核结果必须经过人工确认后才能进入训练集，防止错误结论被再次学习。对于多次出现的同类问题，优先判断根因属于数据、Prompt、RAG召回还是业务规则，再选择微调模型或调整产品逻辑，避免把所有问题都归因于模型参数。

## 5. 当前阶段与下一步计划

当前训练基于阿里云公开数据集，Qwen2.5-VL-3B经LoRA微调后部署在优云智算GPU 4090环境中。数据集通过本地或受控存储读取，不提交第三方闭源模型API；现阶段已完成校内功能验证，但性能数据仍需在统一硬件、网络、并发量和测试集版本下复测。

下一步将扩展不同作物、季节、生育期与拍摄设备的样本，重点测试跨域泛化、环境变化和长尾病害。同时建立按月评估节奏：冻结Golden Set、执行自动回归、人工抽检高风险建议，并监控准确率与幻觉率是否退化。只有模型效果、系统体验和安全指标同时达标，版本才进入试点场景。
