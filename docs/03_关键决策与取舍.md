# 关键决策与取舍

芸析智农的产品设计并非追求技术能力的简单叠加，而是围绕农业弱网、数据隐私、端侧算力和生产风险进行约束下决策。以下四项取舍决定了产品能否从“模型演示”走向可落地的辅助决策工具。

## 决策一：采用“端侧初筛 + 云端复核”

| 方案 | 优势 | 主要代价 |
| --- | --- | --- |
| 完全云端 | 可调用大模型，迭代和维护集中 | 依赖网络，存在延迟、调用成本与数据出域风险 |
| 完全端侧 | 响应快、数据本地处理、离线可用 | 算力和模型容量有限，复杂病例处理能力不足 |
| 端云协同 | 兼顾实时性、隐私与复杂推理 | 任务路由、结果融合和状态同步更复杂 |

**最终决策：以端侧Qwen完成高频初筛，仅将低置信度、结果冲突或复杂问题交由云端LLM复核。**

农业现场网络质量不稳定，如果诊断完全依赖云端，用户可能在最需要结果时无法完成任务。端侧推理时延为0.15—1.23秒，可快速返回基础判断，同时减少原始图片与生产数据外流。云端则承担疑难样本的深度推理，弥补端侧算力不足。该策略增加了架构复杂度，但换取了更稳定的体验、可控的成本和更清晰的数据边界。

## 决策二：选择Qwen2.5-VL-3B并使用LoRA微调

| 方案 | 取舍判断 |
| --- | --- |
| 闭源API | 接入快、能力强，但持续调用成本高，数据需离开本地环境 |
| 大参数开源模型 | 上限较高，但OrangePi AI Pro 20T难以稳定承载 |
| 小参数开源模型 | 可端侧部署，但通用模型在农业细分场景中需要增强 |

**最终决策：采用Qwen2.5-VL-3B作为端侧视觉语言模型，通过LoRA进行领域微调。**

3B规模与现有硬件能力相匹配，LoRA只训练少量增量参数，降低了训练资源、时间和版本迭代成本。微调后域内病害识别准确率超过96.0%，验证了“小模型 + 领域数据”在明确任务中的可行性。选型同时保留模型和数据的本地控制权，但产品化前仍需持续核验开源许可证、模型权重及训练数据的商用边界，避免将“开源”误认为“无限制使用”。

## 决策三：自研监测终端并接入鸿蒙生态

| 方案 | 优势 | 局限 |
| --- | --- | --- |
| 采购成熟设备 | 上线快、硬件可靠性较高 | 协议不一，数据难统一，容易形成新孤岛 |
| 自研基础终端 | 可控制数据格式与交互链路 | 需要投入画板、焊接、调试与维护成本 |

**最终决策：以DHT11、BH1750、DS18B20和4G模块构建最小可用终端，并接入HarmonyOS 6。**

自研的核心目的不是与成熟硬件厂商竞争，而是先打通统一数据入口，确保空气温湿度、光照和土壤温度能够直接进入诊断链路。鸿蒙分布式软总线约8毫秒的时延，使手机采集、PC调度和任务工单跨设备流转成为统一体验。校园小试阶段优先验证数据闭环；进入规模化阶段后，再评估工业级传感器、标准协议接入和第三方硬件兼容。

## 决策四：定位“辅助决策”，而非全自动诊断

| 方案 | 风险判断 |
| --- | --- |
| 全自动诊断与处置 | 流程短，但模型幻觉、误识别可能直接造成用药或减产风险 |
| 辅助决策 + 人工复核 | 操作链路更长，但责任边界和风险控制更清晰 |

**最终决策：AI输出提供风险提示、解释性依据和行动建议，不替代农技专家的最终结论。**

系统对低置信度、三路分析冲突和高风险用药场景主动触发Human-in-the-loop：展示置信度、知识来源和传感器依据，并提供云端复核或农技人员确认入口。人工修改、执行反馈与生产记录通过Device Security Kit安全存证。该边界并非能力不足的退让，而是农业严肃场景下建立用户信任、明确责任并推动商业落地的必要条件。

## 决策总结

四项决策共同指向同一原则：**优先保证真实场景中的可用、可信与可持续，再追求模型能力和产品规模。** 当前架构适用于校园小试和闭环验证；后续需依据真实地块数据，持续评估硬件可靠性、模型泛化、云端成本及人工复核效率。
