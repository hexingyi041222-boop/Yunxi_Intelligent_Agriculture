# 上线与版本迭代

## 1. 上线策略：从可演示走向可复制

芸析智农采用“**先验证闭环、再验证效果、最后验证规模**”的GTM策略。农业场景受作物、季节、网络和种植习惯影响较大，产品不适合一次性全面上线，而应通过四阶段灰度逐步扩大用户、设备和作物范围。

| 阶段 | 上线范围与目标 | 准入/退出门槛 |
| --- | --- | --- |
| 校园验证 | 在可控环境跑通终端采集、OneNet传输、AI建议、多端流转和安全存证 | 病害识别准确率≥96.0%；ViT时延≤1.23秒；端到端任务完成率≥98%；完成不少于3批测试 |
| 示范点试用 | 选择1—2个地块和明确作物，由种植人员真实使用，验证建议是否看得懂、能执行 | 连续运行稳定；高风险错误为0；建议采纳与人工复核数据可追踪；关键问题闭环率≥90% |
| 基地复制 | 扩展至合作社或种植基地，验证多地块、多成员和多设备协同 | 签约≥2个试点场景、覆盖≥5类作物；形成节水≥30%、节肥≥25%的对照验证方法 |
| 区域推广 | 沉淀标准交付、运维和销售方案，面向同区域客户复制 | 累计服务≥10家客户、部署≥50套终端；设备、模型和服务成本处于可持续区间 |

未达到门槛时不进入下一阶段，而是回到模型、硬件或流程环节修复。

## 2. 版本规划（Roadmap）

| 版本 | 产品定位 | 核心能力 | 关键验收结果 |
| --- | --- | --- | --- |
| **V1.0 校园验证版** | 证明技术与业务链路可运行 | 自研终端采集；4G/OneNet链路；鸿蒙App；GPU 4090运行Qwen2.5-VL-3B；云端LLM复核；安全存证 | 软硬件闭环可重复演示，核心AI与系统性能指标达标 |
| **V2.0 试点示范版** | 证明真实场景效果 | 多作物模型与知识库；地块对照实验；每日计划；用户反馈；Bad Case池；设备健康监控 | 覆盖≥5类作物，完成节水节肥验证，疑难样本形成LoRA迭代闭环 |
| **V3.0 商业推广版** | 证明标准化交付和收入模型 | 机构版多设备管理；成员权限；运营看板；计费与服务包；私有化部署；第三方设备标准接口 | 支持10家以上客户和50套终端，形成硬件、订阅及服务收入闭环 |



## 3. 数据驱动的迭代机制

上线后建立“**指标监控—问题归因—小流量验证—版本复盘**”机制。每个诊断任务以task_id关联用户输入、传感器快照、模型与Prompt版本、RAG片段、结果、人工复核和执行反馈。

- **AI建议采纳率低**：区分诊断不可信、解释难懂或操作成本高；优先优化证据展示、计划颗粒度和提醒时机。
- **人工复核率高**：分析是否集中于某类作物、季节或图像条件；将云端复核且人工确认的疑难样本脱敏后加入Bad Case池，用于RAG补充或LoRA二次训练。
- **任务完成率下降**：按图片上传、SSE返回、TTS播放和跨端同步拆解漏斗，定位系统或交互断点。
- **误操作率上升**：回放点击路径和失败原因，减少表单字段、重复入口与不清晰提示。

模型更新必须经过Golden Set回归，高风险建议进行人工抽检。新模型先向内部账号开放，再按10%—30%—100%用户比例灰度；任一安全指标或完成率明显退化时自动停止扩量并回滚。

## 4. 风险应对与降级机制

| 风险 | 监控信号 | 降级与恢复策略 |
| --- | --- | --- |
| 弱网或断网 | 上传超时、SSE中断、OneNet数据延迟 | 本地缓存图片和任务；显示最近数据；网络恢复后续传，避免重复提交 |
| 硬件掉线 | 心跳缺失、数据长时间不更新、异常值突增 | App主动提示最后在线时间；暂停基于过期数据的建议；生成检修工单 |
| GPU或模型不可用 | 推理超时、服务错误率上升 | 退回基础规则、RAG问答或历史计划；明确标记“AI诊断暂不可用” |
| 模型低置信度 | 证据冲突、置信度低、高风险用药问题 | 不输出确定性处置，转云端LLM和人工复核 |
| 新版本异常 | 完成率下降、误操作或负反馈升高 | 停止灰度、切回稳定模型与Prompt版本，保留任务数据用于复盘 |

上线原则是：**允许功能降级，但不允许风险被隐藏。**
